# 学习助手 App · 软件框架文档

> 版本 v0.2（补入学情基线 ExamProfile） · 2026-11-14
> v0.1：2026-11-13 需求澄清收敛版
> 本文不是功能清单的罗列，而是把早晨、课间、自习等零散使用情境**归纳为一套软件框架**：两个闭环、一个横切层、一个数据底座、若干可插拔适配器。
> 来源：九轮需求澄清的全部结论。文末附「决策台账」，可逐条核对理解是否有偏差。

## 0. 产品定位

一款运行在**安卓为主**的移动设备上的个人学习助手，同时承担两个角色：

| 角色 | 职责 | 对应原始诉求 |
|---|---|---|
| **秘书** | 提醒日常任务、呈现日程、倒计时 | 「能提醒我日常任务」 |
| **教练** | 发现薄弱点后，用 AI 陪你从「学」走到「会」再到「记住」 | 「并准备好学习资料」 |

不是待办清单 + 网课浏览器的拼装，而是**以「规划」为主干、以「会话」为执行单元、以「费曼复述」为理解检验核心**的闭环系统。

## 1. 框架总览

```
┌─────────────────────────────────────────────────────────────┐
│  L0 策略与开关层（横切）  Preferences / Feature Toggles       │
│  提醒方式 · 开始时机 · 摸底测验 · 内置笔记显隐 · 数据外发范围   │
├──────────────┬──────────────────────────────────────────────┤
│ 闭环① 任务/  │ 闭环② 能力精进                                │
│ 习惯维系      │  发现薄弱 → 建规划 → 会话学习 → 费曼总结       │
│              │      → 复习闭环 → 达成量化目标                  │
│ 任务与提醒    │ 规划管理 · 学习执行引擎 · 复习闭环             │
│ 子系统        │                                              │
├──────────────┴──────────────────────────────────────────────┤
│  L1 能力层（可插拔）                                         │
│  AI 服务层 ─ 能力接口(固定) + Provider 适配器(可换)           │
│  笔记子系统 ─ A/C/D 三通道 + 统一 NoteDocument                │
│  资源适配器层 ─ 分屏跳转 · 文件桥接 · 引用登记 · 本地导入      │
│  高考对齐约束层 ─ 来源 / 考纲标签 / 年份地区 / 题型分值难度    │
├─────────────────────────────────────────────────────────────┤
│  L2 数据底座：本地存储 + 主动/手动保存 + .studypack 全量迁移   │
└─────────────────────────────────────────────────────────────┘
```

**一句话**：两个闭环共用同一个 AI 能力层、同一个笔记/资源接入层和同一个本地数据底座；所有「可选但存在」的行为统一由 L0 管理。

## 2. 领域模型（核心实体）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Task 任务** | `type` = 习惯性 / 一次性；名称、周期、时间、`reminderMode`(振动/声音/无)、`action`(可一键跳转外部 App) | 「早晨推送不背单词」只是**习惯性任务**的一个实例，不是特指 |
| **Plan 规划** | 目标描述 + 量化指标（如 75%）、时间界限（如 15 天）、`startMode`(立即/将来) 两个选项、日历绿色空闲时段、状态 | 规划是主干实体 |
| **Session 会话** | 归属 Plan、时段、阶段状态机、资源集、测验记录、归因记录 | 规划的一次执行单元 |
| **Review 复习闭环** | 固定模式：复述 → AI 纠正 → 反复确认 → 几道练手题 → 进入今日新内容 | 不是二选一，**就是这一套** |
| **NoteDocument 笔记** | `sourceChannel`(A/C/D)、`contentType`(结构化文本 / SVG 笔迹 / PDF 附件 / 外部引用)、关联(规划·会话·知识点)、`aiGenerated` 标记 | 统一笔记模型，见 §3.7 |
| **KnowledgeAsset** | 课程视频引用、题目、测验记录、个性化 AI 笔记 | AI 产出物 |
| **Resource 资源** | `source`（必填）、教材版本/考纲标签、年份地区、题型·分值·难度、`parentId`（母题） | 高考对齐，见 §3.8 |
| **Attribution 归因** | 错因分类、涉及知识点、关联错题、建议动作 | 未达标分支产出，见 §3.4 |
| **ExamProfile 考试档案** | 卷别 / 地区 / 考试模式 / 教材版本 / 知识点树 / 题型枚举 / 分值 / 难度分布 / 命题风格 | **高考对齐约束层的标签词典来源**，见 §3.8.1 |
| **DataPackage** | manifest + 各实体集合 + 资源目录 | 见 §5 |

## 3. 子系统

### 3.1 任务与提醒子系统（闭环①）
- 习惯性任务的周期调度与管理；一次性任务并存。
- 今日日程表视图；「距下一个任务还有多久」倒计时。
- 任务开始前按 `reminderMode` 提醒（振动 / 声音 / 无）。
- 任务的 `action` 支持一键跳转第三方 App（如打开背单词应用）。
- **与闭环②联通**：规划排定的学习时段会写回日程，同样受倒计时与提醒管辖。

### 3.2 规划管理子系统
- 创建：填入目的 + 量化标准（例：精进基本不等式、能解决 75% 相关题目、遇到同类题脑中有思路）。
- 时间界限（例：15 天内）。
- 在日历上挑选**绿色空闲时段**排布学习时间。
- `startMode`：**立即开始 / 将来开始**两个选项（这是字段取值，不是流程分支）。

### 3.3 学习执行引擎（会话状态机）

```
[AI 准备资源] ──► [摸底测验：可选，可跳过] ──► [视频学习 + 笔记]
                                                    │
                                                    ▼
                                              [相关测验]
                                                    │
                              ┌───────────── 达标? ─────────────┐
                              │ 是                          │ 否
                              ▼                                 ▼
                        [总结环节]                      [AI 错因归因]
                   我复述 → AI 纠正 → 反复                │
                        → 确认理解                          ▼
                              │                    [回到费曼复述-纠正]
                              ▼                          │
                   [生成个性化 AI 笔记]                   ▼
                              │                   [再测一遍] ─┐
                              ▼                              │
                   [生成复习计划，纳入该规划] ◄──────────────┘
```

**关键设计**
- 「摸底测验」是**可跳过节点**：先不选它、直接看视频是合法路径。
- 内置笔记区是**可开关节点**：显示/不显示由 L0 控制，关闭时不渲染，但不影响 A/C 通道已归档的内容。
- 总结环节 = 费曼式复述-纠正循环，反复到确认理解为止。

### 3.4 达标判定的**双层语义**（最后一问结论：1+2）

同一个 75%，作用在两个层级：

| 层级 | 含义 | 触发 |
|---|---|---|
| **通过线（Session 级）** | 单次测验正确率 ≥ 75% → 进入总结环节 | 每次会话结束时判定 |
| **目标线（Plan 级）** | 15 天到期时，整体相关题目解决率 ≥ 75%，且「遇到同类题脑中有思路」 | 规划收口时判定 |

**未达标分支（不是简单重学、也不是直接换题）**：
`AI 错因归因 → 继续费曼复述-纠正 → 再测一遍`，循环至通过线。归因记录写回 Plan，用于调整后续会话的资源难度与复习计划权重。

### 3.5 复习闭环（固定模式 2）
下次该规划学习前：`复述上次理解 → AI 纠正 → 反复确认 → 给几道简单练手题 → 进入今天的学习内容`。

### 3.6 AI 服务层（可插拔，选定方案 4）

**能力接口（固定，不随模型变）**：`分析薄弱点` / `检索资源` / `出题` / `判卷` / **错因归因** / `复述纠正` / `生成笔记` / `生成复习计划`。

**Provider 适配器（可换）**：`DeepSeekAdapter`，配置项 `base_url`、`api_key`、`model_id`、思考模式开关。不绑定具体模型，换模型只改配置。

**三条硬约束**
1. **凭证与数据分离**：`api_key` 存系统密钥库（Android Keystore），**不进 `.studypack` 导出包**；换设备重新填一次即可，避免凭证随数据泄露。
2. **最小必要上下文**：数据留本地，外发的只是当次所需内容，且可配置「哪些内容允许出本地」。
3. **优雅降级**：无 key / 无网时，AI 节点标记「待处理」，不阻塞看视频、记笔记、做已有题目。

**接入实操（已查证）**
- Key 唯一入口：`platform.deepseek.com`（与聊天版 `chat.deepseek.com` 是两套，余额不互通）。手机号注册 → 实名认证 → 充值（微信/支付宝，个人学习用 10~50 元通常够用）→ 创建 API key（`sk-` 开头，**只显示一次**）→ 填入 `base_url = https://api.deepseek.com`，OpenAI 兼容格式。
- ⚠️ **型号更正**：你说的「DeepSeek 4.1 Pro」目前**不是正式在售模型名**，只被官方预告过、无可调用 ID。官方定价页在售的只有：

| 模型 ID | 版本 | 输出价（空闲/高峰，元每百万 tokens） | 图像理解 |
|---|---|---|---|
| `deepseek-flash` | V4.1-Flash-1017 | 4 / 8 | 支持 |
| `deepseek-v4-pro` | V4-Pro-0813 | 13.5 / 27 | 不支持 |

  **建议默认 `deepseek-flash`**：便宜、支持图像理解（拍题目截图、讲义图片）、1M 上下文；需要更强推理再切 `deepseek-v4-pro`。这正是可插拔的价值。

> **关于 WorkBuddy 连接器**：它是 WorkBuddy 平台侧让 AI 助手在对话里访问第三方服务的能力，**不是你的 App 能调用的运行时能力**。当前会话也只挂了一个未连接的连接器，并无学科网/B站连接器。它只在**开发阶段**有用（例如帮我把你发的资料整理好、灌进 App 本地资料库）。

### 3.7 笔记子系统（A + C + D 三通道 + 统一模型）

| 通道 | 形态 | 数据能否进我们的库 |
|---|---|---|
| **A 系统分屏 / 跳转** | 已买断的 Notein，同屏两块区域或一键跳转 + 自动回位 | ❌ 原始笔迹入不了库，只登记「外部引用 + 可选快照」 |
| **C PDF 桥接** | App 导出讲义/题目 PDF → Notein 批注 → 导回归档 | ✅ 以文件形式可带走 |
| **D 内置笔记区** | App 内真有一块笔记区域，**可显示 / 不显示** | ✅ 完全归我们、随包导出 |

**为什么不能把 Notein 直接内嵌**：Notein 无公开 SDK/API；Android/iOS 都不允许 A 应用把 B 应用的界面当作自己的 View 运行（Android 双窗格 Activity 嵌入也只限同一 App 内部）。买断 = 使用权，不等于可集成权。

**D 通道的技术路线（GitHub 调研结论）**：能塞进 App 当一块区域的必须是**库/SDK**，而几乎所有开源手写笔记项目（saber / butterfly / AppFlowy / xournalpp）都是**完整 App**，且多为 GPL/AGPL 强传染，搬不进来。结论是「**整件都不合，零件全合**」——用 MIT 零件自组装：

| 零件 | 许可证 | 用途 |
|---|---|---|
| tiptap / lexical | MIT | 结构化文本、块编辑（便于 AI 生成笔记） |
| perfect-freehand | MIT | 压感手写笔迹平滑，复刻 Notein 手感 |
| MuPDF / Pdfium（开源）或 ComPDFKit（商业、省事） | — | PDF 渲染与批注，承接 C 通道 |

避开：`tldraw`（自定义许可，商用需保留水印或购买约 $6000/年授权）、各类 AGPL/GPL 整件。

### 3.8 资源适配器层 + 高考对齐约束层

**四种统一接入模式**（把之前为 Notein 设计的三通道泛化）：`分屏/跳转(A)` · `文件桥接归档(C)` · `引用登记 + 跳转` · `本地导入(③)`。以后接任何外部服务都不动主流程。

**外部源现状（已查证）**

| 平台 | 结论 | 可行做法 |
|---|---|---|
| **学科网** | 有开放平台 `open.xkw.com`，提供试题/试卷/视频/变式题/错题接口，OAuth、页面嵌入与跳转模式，标签体系覆盖考纲与教材版本 —— 最贴高考；但**面向企业商业合作**，需签约付费与资质 | ① 你用自有账号下载/导出资料 → 导入 App 本地库；② 应用内用其跳转模式；③ 正式 API 对接留到有资质以后 |
| **B站** | 官方开放平台权限主要面向 UP 主管理自有内容，**不含关键词搜索**；网页接口需 wbi 签名、高频返回 412；爬虫违反用户协议 | **不搬视频、不抓取**，只做「引用登记 + 一键跳转 B站 App」，本地只存标题/BV号/时长等元数据 |

**高考对齐约束层（硬规则）**
- 每份资源/题目强制带 `source`、教材版本/考纲标签、年份地区、题型·分值·难度。
- **AI 的角色从「生成者」降级为「检索匹配 + 讲解 + 基于真实母题的变式」**；变式题必须挂靠母题来源，**禁止无来源的题冒充高考题**。
- 资料优先级：`③ 你自己的资料` ＞ `学科网权威题库` ＞ `B站视频（仅跳转）` ＞ `AI 生成（受限）`。

> 对你那句「想让 AI 自己升级的话和考试内容和风格相差很大」的理解：**若让 AI 凭空生成题目/资料，会与高考真实内容、命题风格相差很远**，因此必须以真实题库和你自己的资料为准。若理解有偏差请纠正。

#### 3.8.1 学情基线：`ExamProfile`（问题 1 结论，2026-11-14）

上面的「教材版本/考纲标签」原本只是字段名，没有词典来源。现由用户背景查证后落定为一份**可执行配置实体**，它定义了整个标签体系的取值。

**已确定值**

| 字段 | 值 |
|---|---|
| 地区 / 学校 | 广东深圳 / 深圳中学 |
| 卷别 | **新高考 I 卷（新课标 I 卷）**，语数英全国卷 |
| 考试模式 | `3+1+2`；**数学不分文理**；选考科目广东自主命题 |
| 教材 | **人教 A 版（2019 新版）**（`必修第一册 / 选择性必修第一~三册`） |
| 题型枚举 | 单选 8×5 分 / 多选 4×5 分 / 填空 4×5 分 / 解答 6 题 70 分，满分 150 |
| 主干知识 | 三角函数 / 数列 / 统计与概率 / 立体几何 / 函数与导数 / 解析几何 |
| 难度分布 | 基础 : 中档 : 难题 ≈ 5 : 3 : 2 |
| 命题风格（2026） | 去套路化、题型顺序重组、情境化建模增多、重思维轻计算、开放探究 + 新定义压轴、**回归教材** |

**框架层面的三点影响**

1. **知识点树直接挂靠教材目录**，而非 AI 自拟标签。首个锚点即用户原始情境中的薄弱点：
   `人教A版·必修第一册 → 第二章 一元二次函数、方程和不等式 → 2.2 基本不等式`。
   这让「贴切」变成**可校验**（能比对章节/题型/分值），而不是靠主观判断。
2. **为「AI 只做检索匹配 + 讲解 + 基于母题的变式」补上硬理由**：真题正在「去套路化 + 情境建模 + 开放探究」上发力，而这恰是模型最容易生成模板化题目的地方——用户的直觉与真题分析一致，因此"禁止无来源题冒充高考题"不是保守，是必需。
3. **`ExamProfile` 随 `.studypack` 一并导出**：换设备、换年份、换教材时只需替换这一份配置，知识点树、题型枚举、资料筛选规则全部跟着走，「贴切高考」不因迁移而丢失。

> 教材版本的小提醒：深圳高中数学同时存在人教 A 版与苏教版并行的情况；深中数学组深度参与人教 A 版教材编写与示范课，故按 **人教 A 版** 落定。若你课本封面是别的版本，说一声，只改这一处配置即可。

### 3.9 策略与开关层（L0，横切）

所有「有这个功能，但用不用由我定」的点统一归此层，不各自造开关：

| 策略点 | 取值 |
|---|---|
| 提醒方式 | 振动 / 声音 / 无 |
| 开始时机 | 立即 / 将来 |
| 摸底测验 | 显示 / 跳过 |
| **内置笔记区** | **显示 / 不显示**（全局默认 + 单次会话可临时改） |
| 数据外发范围 | 可配置白名单 |
| 复习模式 | 固定模式 2（不可配） |

### 3.10 数据持久化与迁移子系统

- 全部数据本地存储；支持主动（自动快照）与手动保存。
- **固定格式导入/导出所有数据，用于其它设备使用**（格式由本文设计，见 §5）。

## 4. 平台与技术选型

| 设备 | 定位 |
|---|---|
| vivo S7 手机 | 主用；屏幕小，分屏基本不可用，A 通道**自动降级为一键跳转 + 回位** |
| 联想 13 英寸安卓平板 | **A 通道分屏主战场**，同屏两块区域体验最好 |
| 家人 iQOO / 红米 | 同为安卓，但 OriginOS / HyperOS 分屏能力不一致 |
| 家人 iPhone | iOS 旁支 |

**推论**
1. A 通道做「**能力探测 + 自动降级**」：检测是否支持分屏/自由窗口 → 支持则并排，否则退回跳转。不写死。
2. **技术栈建议 Flutter**：一套代码覆盖全部安卓机型 + 保留 iOS 可能；手写笔记生态（saber、butterfly 均为 Flutter）已在安卓平板验证成熟。
3. **iPhone 不硬做完整客户端**。「数据可移植 ≠ 应用跨平台」——原话是「数据能在其它设备使用」，不是「App 必须在 iPhone 上跑」。iPhone 走 `.studypack` 包 + 轻量查看器（网页/PWA）读取即可。
4. 因此「数据迁移」从末尾的「其它要求」**提升为框架一等模块**。

## 5. 数据格式设计：`.studypack`（由本项目设计）

### 5.1 设计目标
全量可携带 · 开放可读 · 不锁死在特定程序 · 自描述可校验 · 不含密钥与第三方版权内容。

### 5.2 目录结构

```
studypack-YYYYMMDD-HHMM/
├── manifest.json          # 版本/schema版本/导出时间/设备/校验和
├── preferences.json       # 策略与开关层全部配置
├── exam_profile.json      # 学情基线：卷别/教材/知识点树/题型/难度（§3.8.1）
├── tasks.json             # 习惯性任务 + 一次性任务
├── plans.json             # 规划（目标、量化指标、时限、开始时机、空闲时段）
├── sessions.json          # 会话状态机记录、测验记录、归因记录
├── notes.json             # NoteDocument 索引（含 A/C/D 来源通道、AI生成标记）
├── review.json            # 复习计划与状态
├── resources.json         # 资源引用：只存元数据与出处，不存第三方内容
└── assets/
    ├── pdf/               # 讲义、C 通道批注回传 PDF
    ├── ink/               # SVG 笔迹（D 通道）
    └── images/            # 图片、题目截图
```

### 5.3 规则
1. **纯开放格式**：JSON（UTF-8）+ SVG + PDF + Markdown，别的程序也能读。
2. **凭证不进包**：`api_key` 排除在外，换设备重新填。
3. **第三方版权内容不进包**：B站视频、学科网题库只存引用与考纲标签；你自行导入的资料属本地资产，随包带走。
4. **自描述 + 校验**：`manifest.json` 带 `schemaVersion` 保证向前兼容，带 `checksum` 供导入时校验完整性。
5. **带走的不是一堆文件，是带考纲标签、可追溯的结构化资料** —— 换设备后「贴切高考」这一约束不丢。
