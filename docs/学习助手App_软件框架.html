v1.0 定稿 · 完整回顾 + 七问收口 · 2026-11-14

学习助手 App · 需求与框架定稿

版本 v1.0（定稿）· 2026-11-14 v0.2：补入学情基线 ExamProfile（问题 1） v0.1：2026-11-13 需求澄清收敛版

本文不是功能清单的罗列，而是把早晨、课间、自习、考前等零散使用情境归纳为一套软件框架：两个闭环、一个横切层、一个可插拔能力层、一个数据底座。 v1.0 收口说明：九轮澄清 + 七轮待拍板问题全部收敛，本文即「App 内容」的唯一真源。§1 是应要求做的完整回顾与自查，§9 说明后续分工。

后续分工：页面结构与整体画风 → 交给千问（见 docs/给千问_页面设计交接简报.md）；编码实现 → 由本助手承担。三者共用本文作为输入基准。

0. 产品定位

一款运行在安卓为主的移动设备上的个人学习助手，同时承担两个角色：

角色 职责 对应原始诉求
秘书 提醒日常任务、呈现日程、倒计时 「能提醒我日常任务」
教练 发现薄弱点后，用 AI 陪你从「学」走到「会」再到「记住」 「并准备好学习资料」

不是待办清单 + 网课浏览器的拼装，而是以「规划」为主干、以「会话」为执行单元、以「费曼复述」为理解检验核心的闭环系统。

1. 完整回顾（仔仔细细核对理解）

1.1 起点：你最初描述的使用情境，逐句拆开

情景 A · 早晨起床 - 打开手机，App 推送今天最近的一个任务——例：「打开不背单词去背单词」，并支持一键跳转打开那个应用； - 同时把今天的既定日程表完整呈现供浏览。 - 后续澄清：这个「背单词」不是特指，是习惯性任务的一个实例；「一键打开」= 任务带一个跳转外部 App 的执行动作。 - 再后续补充：这个情境的实现形态改为桌面小组件（常驻桌面、只显示最近任务 + 倒计时），见 §4.2。

情景 B · 自由时间 / 碎片时间 - 打开手机能看到距离下一个任务还有多久（倒计时）； - 可在任务开始前按设定方式提醒：振动 / 声音 / 无（三选一）。

情景 C · 发现薄弱点 → 新建规划（核心闭环） 1. 上完数学课，意识到「基本不等式」薄弱，想强化； 2. 在 App 里新建规划，填入： - 目标：精进基本不等式、能解决 75% 的相关题目、且「以后遇到相关题目时脑中有思路」； - 时间界限：15 天内； - 在日历上挑选绿色空闲时段排学习时间； - 立即开始 / 将来开始两个选项（后澄清：这是告知「存在这两个选项」，不是让我选）。 3. AI 分析后，为当下这个时段准备好：课程视频资源 + 相关题目； 4. 先不做 AI 的摸底测验，直接看视频（后澄清：摸底测验「不是一定要的，但是有的」= 可选环节）； 5. 边看边用内置笔记（Notein 式）记录； 6. 看完后做相关测验，达标进入下一环节； 7. 总结环节：我先向 AI 复述理解 → AI 纠正 → 反复几轮 → 确认理解； 8. AI 生成这份知识的个性化 AI 笔记； 9. AI 制定复习计划并纳入该规划；复习方式（后澄清：不是二选一，就是模式 2）： 下次学习前 → 先复述上次理解 → AI 纠正 → 几道简单练手题 → 再进入今天的新内容。

其它（数据） - 数据本地储存；支持主动 / 手动保存； - 以固定格式导入 / 导出所有数据，供其它设备使用。后澄清：格式由我设计，需求本质是「全量数据可携带 / 可迁移」，不是要用户来定格式。

1.2 最重要的一次元纠正

「你不是要从表面的使用情境来看，你是要深层次的把使用情境归纳于一个软件框架。」

这条决定了本文的写法：不复述情节，而是抽象实体、闭环与层次。此后每一轮补充都按这个标准处理。

1.3 你逐条纠正过我的理解（5 条）

# 你的纠正 我修正为
1 「不背单词」可归类于习惯性任务，不是单指背单词 抽象为「周期性重复的例行任务」，背单词只是一个实例
2 「立即开始 / 将来开始」是告诉我有两个选项 Plan.startMode 上的一个字段取值，不是流程分支、不是待选答案
3 「先跳过摸底测验」是告诉你不是一定要的，但是有的 学习流程里的可跳过节点（Optional Stage），功能存在、用不用由你定
4 复习不是 2 选 1，就是模式 2 复习闭环固定为「复述→纠正→练手→新内容」，不可配
5 导入导出固定格式由你设计 需求本质是「全量数据可携带」，格式是设计产物（§6）

1.4 澄清轮次的结论（在进入 7 问之前）

主题 结论

AI 来源 选 4 可插拔接口（不绑定模型）；默认 DeepSeek；「4.1 Pro」非正式在售型号，建议 deepseek-flash；api_key 存 Keystore、不进导出包；最小必要外发；无网优雅降级

学情基线 深圳中学 → 查证补全 新高考 I 卷 + 人教 A 版 2019；「基本不等式」正锚在必修一 2.2 → 新增 ExamProfile

1.6 交付前自查：最容易理解偏的 8 处（请重点核对）

# 我的理解 若偏了会影响什么
1 数据可移植 ≠ 应用跨平台：iPhone 不做完整客户端，只走 .studypack + 轻量查看器 平台工作量与一期范围
2 法二爬虫「不做」：基于合规判断否掉；你随后给出截图方案（等于接受降级），但未明说「放弃自动同步」 课表是手动刷新还是自动同步
3 复习闭环固定模式 2、不可配；其余「可选但存在」的都归 L0 状态机是否要给复习做配置
4 75% 是双层（会话通过线 + 规划目标线），不是单一数字 达标判定与收口逻辑
5 ① 纯开放不加密 = 别人拿到包即可读全部学习轨迹（已提示，你仍选 ①） 隐私边界；api_key 仍排除在包外
6 教学区域禁用电子设备 → 纸质/打印态是刚需；进考场前可用手机 → 屏幕速览态有效（我上一轮的担心已收回） 速查卡要做双渲染
7 内置笔记区「可显隐」不等于 A/C 通道归档内容可丢弃；隐藏只是不渲染 数据完整性
8 AI 从「生成者」降为「检索匹配 + 讲解 + 基于真实母题的变式」，禁止无来源题冒充高考题 整个资源层的可信度

以上任何一条与你的本意不符，说一声即可；本次按「无问题」继续，改文档后重传最终版。

3. 领域模型（核心实体）

实体 关键字段 说明
Task 任务 type = 习惯性 / 一次性；名称、周期、时间、reminderMode(振动/声音/无)、leadMinutes、action(一键跳转外部 App) 「早晨推送背单词」是习惯性任务的一个实例
Plan 规划 目标 + 量化指标(75%)、时间界限(15天)、startMode(立即/将来)、slots(引用 SlotPool)、状态 主干实体
Session 会话 归属 Plan、时段、capacityMinutes、阶段状态机、资源集、测验记录、归因记录、sessionIntent 规划的一次执行单元
Review 复习闭环 固定模式：复述 → AI 纠正 → 反复确认 → 几道练手题 → 今日新内容 不可配
SlotPool 时段池 多来源 Slot 集合；每个 Slot 带 deviceAvailable、capacityMinutes、confirmed(当天确认状态) 「绿色」不是规则，是池（§4.3）
SlotTemplate 常驻模板 4 个默认时段：07:00–07:30 / 13:00–13:30 / 17:20–18:20 / 21:30–21:50；可开关、当天可取消 法三
SchoolCalendar 校源日程 课程 + 考试 + 活动；来源 = 截图导入 / 小程序桥接；带「教学区域/课间禁用」过滤 法一/法二；校运会由此供给（§4.3）
WidgetView 桌面组件 最小态：最近一个任务 + 倒计时；点击 → 今日视图 / 全局日历 §4.2
WeakPoint 薄弱点 anchorId、三维标签(知识结构/高考能力/费曼暴露)、薄弱程度、证据(题号+复述原句)、一行考前提醒 归因产出（§4.4）
ExamReminderCard 考前速查卡 同源双渲染：屏幕态 / 打印态(黑白可读) 进考场前用手机，教学区域用纸质
NoteDocument 笔记 sourceChannel(A/C/D)、contentType(结构化文本/SVG笔迹/PDF附件/外部引用)、aiGenerated、anchorId 两份独立存：AI 笔记 / 我的笔记
AnchorLink 关联表 anchorId ↔ 两份笔记的块/页 本地索引，不需要 AI（§4.7）
Resource 资源 source(必填)、教材版本/考纲标签、年份地区、题型·分值·难度、parentId(母题)、变形档位 高考对齐（§4.8）
ExamProfile 考试档案 卷别 / 地区 / 模式 / 教材版本 / 知识点树 / 题型枚举 / 分值 / 难度分布 / 命题风格 标签词典来源（§4.8.1）
DataPackage manifest + 各实体集合 + assets 目录 §6

4. 子系统

4.1 任务与提醒子系统（闭环①）

  • 习惯性任务的周期调度与管理；一次性任务并存。
  • 今日日程表视图；「距下一个任务还有多久」倒计时。
  • 任务开始前按 reminderMode + leadMinutes 提醒（振动 / 声音 / 无）。
  • action 支持一键跳转第三方 App。
  • 与闭环②联通：规划排定的学习时段写回日程，同样受倒计时与提醒管辖。
  • 设备禁用时段自动静默：教学区域 / 考场内不响不亮屏（对应「无」）。

4.2 全局时间视图与桌面小组件（问题 3 结论）

层级 内容
WidgetView（最小态） 常驻桌面，只显示最近一个任务 + 倒计时；点一下跳转
点开 → 今日视图 今天的既定日程
点开 → 全局日历 全局、已描述任务；任务 / 规划学习 / 校历三层叠加
  • 原始情境 A（早晨推送最近任务）由「通知推送」改为常驻 Widget 实现，且更优：不用打开 App 就能看到最近任务与倒计时。
  • SlotPool 是这张日历里被判定为「可学习」的子集。
  • 提前量三层：全局默认（可设 5 分钟）＋ 快捷预设 2 / 5 min ＋ 自定义输入；设置时机在「设计规划时」，每次排期可覆盖。
  • 技术约束：提前 2 分钟要求精确调度（系统精确闹钟，不能靠普通定时轮询）；Widget 不能秒级刷新，倒计时按分钟级更新以省电。

4.3 时段池 SlotPool（问题 2 结论）

「绿色空闲时段」不是一条判定规则，而是一个多来源、会变、需当天确认的时段池。三种「法」是同一池子的三种数据来源，不是三套逻辑：

来源 本质 确定性 数据进库方式
法一 在校时段，按课程表手动标绿 按周/按天变动 你发课程表截图 → 识别成结构化 SchoolCalendar
法二 同一份课程表的自动获取（学校小程序） 同法一 不做爬虫；降级为跳转查看 + 文件桥接
法三 校外常驻作息模板，每天从中勾选 基本每天有、但可取消 SlotTemplate 预置 4 段，按天确认
自定义 一次性临时时段（校运会等） 一次性 手动新增；部分可由 SchoolCalendar 活动自动供给

四条判定与约束 1. 绿色 = 空闲 ∧ 设备可用 ∧ 能用手机 ∧ 时长够。课间用不了手机、教学区域禁用电子设备 → 这两类间隙被自动过滤；它也解释了「一天在校就那么几个时段」。 2. 法一与法二是同一份数据的两种拿法；法二不可行时，法一就是自带的降级路径。 3. 一切可变：课表会变、模板当天不一定有、临时时段会冒出来 → 时段池按天确认 / 可增删改，时段消失时排期要能重排。截图导入是批量一次性导入，不是实时同步，建议换课/大考周更新一次。 4. 容量约束：四个常驻时段合计 140 分钟/天（30+30+60+20），其中 20/30 分钟是碎片。一次完整会话（视频→费曼→测验）装不进 20 分钟，因此 SlotPool 与 Session 联动：按时段容量匹配学习环节——碎片时段放复习闭环（复述→纠正→练手题），整块时段（17:20–18:20）才排新内容；必要时会话拆分并跨时段续接。

SchoolCalendar 两处升格 - 智慧校园「教学管理 → 日程」里不只有课表，还有考试与活动 → 实体由 CourseTable 升格为 SchoolCalendar；校运会这类临时空档由此自动供给，自定义保留为兜底。 - PDF 中间态可省：截图 → AI 识别 → 直接落成结构化 JSON 进本地库；PDF 只留作「人能翻的归档副本」。只有结构化数据才能过滤课间、算空闲、随包带走。截图可能带姓名/班级/教室 → 走最小必要外发 + 本地脱敏（deepseek-flash 支持图像理解）。

法二为何不做爬虫（已查证）：小程序非公开接口 + 登录态/会话票据的模拟调用需主体授权；绕过落在《反不正当竞争法》十三条、《网络安全法》《个人信息保护法》范围内，情节严重涉《刑法》285 条，平台检测到异常抓包会封号。合法路径只有「正式 API / 数据导出 / 合作方通道」。深中课表挂在腾讯智慧校园 + 电子班牌体系（走班制、刷校园卡查课表），恰属需账号登录的非公开接口。故法二降级为跳转查看（A 通道同构）+ 若支持分享图片则文件桥接（C 通道同构）。

4.4 错因归因与薄弱点（问题 4 结论）

你选 ① 知识结构 + ② 高考能力 + ③ 费曼暴露 三维结合，排除 ④ AI 自由归因——这与 §4.8「不让 AI 凭空造题」是同一倾向：要预设维度、可校验，不要黑箱。④ 最容易产出「基础不牢」这类无法验证的结论。

错因归因 的产出从「过程记录」升格为 WeakPoint 条目 + ExamReminderCard：不写分析报告，而是可定位、一眼扫完、直接能用的条目，精确到知识点树叶子节点。

字段 示例（用最初的薄弱点）
知识点节点 人教A版·必修一·2.2 基本不等式 → 等号成立条件
① 知识结构 公式使用条件记混
② 高考能力 去套路化迁移（换情境就不会查等号）
③ 费曼暴露 假懂（说得出「一正二定三相等」，一做题就漏查）
薄弱程度 高（3 次错，含 1 次假懂，跨 2 个时段重复）
证据 第 3、7 题；复述原句「…」
考前提醒（一行） 「一正二定三相等，先问等号取不取得到」
  • 三维不是三选一，是同一条错因打三个轴：是什么不会 / 哪类题暴露 / 是真不懂还是假懂；标签复用 §4.8 已有的考纲·题型词典。
  • 薄弱程度量化（频次 / 是否跨时段重复 / 是否假懂加权），驱动复习权重、练手题难度、Widget 考前速览态。
  • 闭环你第一句话的目标：「以后遇到相关题目时脑中有思路」= 把薄弱点标记内化成看到题目时的即时反应。速查卡是脚手架，终点是不用看卡也能条件反射想起那个坑——正是费曼反复纠正要达成的结果。
  • 双渲染同源：ExamReminderCard 生成屏幕态（Widget 考前速览 / 进考场前用手机）与打印态（教学区域可用，黑白打印仍可读），内容一字不差，随包导出。

4.5 变式题与临场意图（问题 5 结论）

主路径 = ② 按 WeakPoint 薄弱程度自适应 + ④ 变形强度四档递进（同条件换数字 → 换情境 → 换设问 → 开放探究）。

「有时候想写难题挑战自己、有时候只想写中档题刷自信」不是策略配置，是临场意图 → SessionIntent，进练习前点一下：

取值 行为
跟随系统（默认） 走 ②④
挑战 抬难度、直上开放探究档
刷自信 锁中档、变形档不升
  • 三个实例串成一条线：笔记区显隐 / 跳过摸底测验 / 难度临时选，都是「App 给流程，当下这一步你定」，归进 L0 与可跳过节点，不新造机制。
  • ④ 最高档「开放探究」正好供给「挑战」意图 → 题库需备到压轴档，不能只备基础/中档。
  • 防污染设计：手动选「刷自信」做对中档题，不能算薄弱程度下降的证据。做题记录带 来源模式 = 自适应 / 意图覆盖，归因只认前者，否则 WeakPoint 评级与复习计划会被一次「刷自信」拉歪。

阶段流转
1 资源就绪AI 准备资源 → 摸底测验（可选，可跳过） → 视频学习 + 笔记
2 测验相关测验 → 判定达标
3a 达标 → 总结我复述 → AI 纠正 → 反复 → 确认理解 → 生成个性化 AI 笔记 → 生成复习计划纳入规划
3b 未达标 → 归因回路AI 错因归因（产出 WeakPoint）→ 回到费曼复述-纠正 → 再测一遍 → 回到第 2 步，循环至通过线
4 复习闭环（固定）下次学习前：复述上次理解 → AI 纠正 → 反复确认 → 几道简单练手题 → 今日新内容
  • 「摸底测验」是可跳过节点；内置笔记区是可开关节点（关闭时不渲染，但不影响 A/C 已归档内容）。

4.7 笔记子系统（问题 6 结论：④ 分开存 + 双向关联）

你选 ④，排除 ③ 的理由是「合订太冗长」——与 Widget 最小态、考前卡一行同属信息克制偏好。

通道 形态 数据能否进我们的库
A 系统分屏 / 跳转 已买断的 Notein，同屏两块区域或一键跳转 + 自动回位 ❌ 原始笔迹入不了库，只登记「外部引用 + 可选快照」
C PDF 桥接 App 导出讲义/题目 PDF → Notein 批注 → 导回归档 ✅ 以文件形式可带走
D 内置笔记区 App 内真有一块笔记区域，可显示 / 不显示 ✅ 完全归我们、随包导出

「快速对应」靠结构化锚点，不靠内容比对，默认不需要把笔记交给 AI： - AI 笔记的每个文本块、我的笔记的每一页/每一笔，在保存那一刻就打上同一个 anchorId = 知识点节点ID + SessionID + WeakPointID（复用 ExamProfile / 归因已在用的 ID，不新造）。 - 「对应」= 本地数据库按 ID 索引查询，毫秒级、纯本地、离线可用。 - 交互：AI 笔记段落旁角标（如 笔迹 2）→ 点开拉出该锚点下我的笔迹；反向在笔迹页也能跳回 AI 笔记段落。

什么时候才需要交给 AI（三档）

情形 要不要交给 AI 说明
建立 / 查看对应、双向跳转 不需要 本地索引即可
想让 AI 读笔迹后补/改 AI 笔记、纳入复习 需要，但由你主动触发 只送该锚点下那一小段，最小必要外发 + 脱敏
A 通道写在 Notein 里的笔迹 想处理时才需要 原件始终是外部引用 + 快照；只有 C 通道归档回来的那份可被处理

手写识别边界：D 通道结构化文本 AI 可直读；A/C 的图片/PDF 笔迹要读需 OCR/视觉理解，但识别结果只作「可检索摘要」，绝不覆盖原始笔迹，识别错也不污染数据。

D 通道技术路线（GitHub 调研结论）：能塞进 App 当一块区域的必须是库/SDK，而几乎所有开源手写笔记项目（saber / butterfly / AppFlowy / xournalpp）都是完整 App 且多为 GPL/AGPL，搬不进来 —— 「整件都不合，零件全合」，用 MIT 零件自组装：

零件 许可证 用途
tiptap / lexical MIT 结构化文本、块编辑（便于 AI 生成笔记）
perfect-freehand MIT 压感手写笔迹平滑，复刻 Notein 手感
MuPDF / Pdfium（开源）或 ComPDFKit（商业、省事） — PDF 渲染与批注，承接 C 通道

避开 tldraw（自定义许可，商用需保留水印或约 $6000/年授权）与各类 AGPL/GPL 整件。

4.8 资源适配器层 + 高考对齐约束层

四种统一接入模式：分屏/跳转(A) · 文件桥接归档(C) · 引用登记 + 跳转 · 本地导入。以后接任何外部服务都不动主流程。

平台 结论 可行做法
学科网 有开放平台 open.xkw.com，试题/试卷/视频/变式题/错题接口，标签覆盖考纲与教材版本 —— 最贴高考；但面向企业商业合作，需签约付费与资质 ① 自有账号下载 → 导入本地库；② 应用内跳转模式；③ 正式 API 留到有资质以后
B站 官方开放平台主要面向 UP 主管理自有内容，不含关键词搜索；网页接口需 wbi 签名、高频 412；爬虫违反用户协议 不搬视频、不抓取，只做「引用登记 + 一键跳转」，本地只存标题/BV号/时长等元数据

高考对齐约束层（硬规则） - 每份资源/题目强制带 source、教材版本/考纲标签、年份地区、题型·分值·难度。 - AI 的角色从「生成者」降级为「检索匹配 + 讲解 + 基于真实母题的变式」；变式题必须挂靠母题来源，禁止无来源的题冒充高考题。 - 资料优先级：③ 你自己的资料 ＞ 学科网权威题库 ＞ B站视频（仅跳转） ＞ AI 生成（受限）。

对你那句「想让 AI 自己升级的话和考试内容和风格相差很大」的理解：若让 AI 凭空生成题目/资料，会与高考真实内容、命题风格相差很远，因此必须以真实题库和你自己的资料为准。

6.3 规则（问题 7 结论：① 纯开放不加密）

  1. 纯开放格式、不加密：JSON（UTF-8）+ SVG + PDF + Markdown，任何设备、别的程序都能直接读；导入无需口令。代价：拿到文件即可读到全部学习轨迹（学校、班级、薄弱点、错题），已提示并由你确认接受。
  2. 凭证不进包：api_key 排除在外，换设备重新填。
  3. 第三方版权内容不进包：B站视频、学科网题库只存引用与考纲标签；自行导入的资料属本地资产，随包带走。
  4. 自描述 + 校验：manifest.json 带 schemaVersion 与 checksum。
  5. 考前速查卡双渲染同源导出：屏幕态与打印态内容一致。
  6. 带走的不是一堆文件，是带考纲标签、可追溯、带关联锚点的结构化资料 —— 换设备后「贴切高考」与「两份笔记对得上」都不丢。
