待拍板 · 绿色语义冲突：千问 tokens 把松绿定义为「达标/完成/≥75%」，组件规范里又用它标「可学习时段」和 Stepper「已过」——一绿三义，与交接简报硬约束 2（绿色 = 可学习空闲时段专色，不得挪作成功/完成）冲突。 本稿按方案 A 出图：松绿只留给时段，达标改用墨蓝实心 + 对勾/文字，Stepper 已过用墨蓝填充；4 色不增不减。最终由千问或用户拍板。

图例：绿色块 = 可学习空闲时段（唯一语义）　·　琥珀 = 倒计时/进行中　·　朱砂 = 薄弱/未达标　·　描边 + 文字为打印态冗余编码

04A 通道分屏：三形态 + 降级（Y900 独占主战场）

形态 ①　优先

系统分屏 60:40

Notein
手写

检测到多窗口 / Activity Embedding → App 窗口降到 Medium，自动切单栏 + NavigationRail。顶部留「返回学习会话」。

形态 ②

自由窗口 / 悬浮窗

学习 App（紧凑单栏）
Notein 悬浮窗

系统支持自由窗口时用；App 收成紧凑单栏。笔迹归档仍走 C 通道 PDF 桥接。

形态 ③　降级

一键跳转 + 自动回位

学习 App 全屏　→　切到 Notein　→　自动回到会话

分屏不可用时与手机同构。A 通道只登记「外部引用 + 可选快照」，原始笔迹入不了我们库。

能力探测顺序：④ App 内 D 通道（永远可用，数据 100% 归本地）→ ① 系统分屏 → ② 自由窗口 → ③ 跳转降级。 C 通道（导出讲义 PDF → Notein 批注 → 归档回来）在所有形态下补齐「笔迹能带走」这一缺口。
