## 3. 设计策略：不是同一套 UI 放大，而是两台设备分工

### 3.1 把设备差异归纳回框架

用户给的 `SlotPool` 四段共 140 分钟/天，其中 20/30 分钟是碎片、60 分钟是整块。两台设备正好各承接一半：

> **vivo S7 = 碎片端**（20/30min）：看一眼最近任务、倒计时、提醒、复习复述、考前速览 → 主要跑**闭环① 任务/习惯维系**。
> **Y900 = 整块端**（60min）：视频学习、测验、费曼对话、手写笔记、打印 → 主要跑**闭环② 能力精进**。

这条分工决定了一切样式取舍，而不是「手机单栏、平板也单栏只是字更大」。

### 3.2 断点与导航形态（Material 3）

| Class | 有效宽度 | 触发 | 导航 | 内容栏数 |
|---|---|---|---|---|
| **Compact** | < 600dp | vivo S7 竖屏（360dp） | **底部 4 Tab**（千问定稿：今日/规划/笔记/我的），高 56–64dp | 单栏，每屏一件事 |
| **Medium** | 600–840dp | S7 横屏、**Y900 被系统分屏后的半屏** | `NavigationRail`（72–80dp 图标栏） | 双栏 list-detail，或单栏 + 侧栏 |
| **Expanded** | ≥ 840dp | Y900 全屏横屏（约 1536–1920dp） | 常驻 `NavigationRail`（96dp，可展开 240dp 带文字）或 `NavigationDrawer`；**取消底部 Tab** | 双栏 / 三栏（Rail + 列表 + 详情） |

**关键规则**：断点按**当前窗口宽度**判断，不按设备型号判断。Y900 一旦与 Notein 系统分屏，App 窗口宽度掉到 Medium，必须自动切回单栏 + Rail，不能写死 expanded 布局——这正是框架里「能力探测 + 自动降级」在样式层的落点。

### 3.3 配色冲突：绿色只该有一个意思

千问 tokens 把松绿 `#2E7D5B` 定义为 `Success · 达标/完成/≥75%`，同时组件规范又写「绿=可学习时段」、Stepper「绿=已过」。而交接简报**硬约束 2** 要求：**绿色 = 可学习空闲时段的专色，不得挪作「成功/完成」**。同一份日历/今日页上「这段能学」和「这个达标了」都变绿，正是要防的歧义。

按边界声明，我不擅自改千问定稿，只给方案，**由千问或用户拍板**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 松绿 `#2E7D5B` **只留给可学习时段**（日历色块、时段池、任务卡左色条）；达标/完成/≥75% 改用**墨蓝 `#204066` 实心 + 对勾或文字**；Stepper「已过」用墨蓝填充；朱砂保留给薄弱/未达标/挑战；琥珀保留给倒计时/进行中 | 改动最小，绿色语义独占，4 色不增不减；打印态靠描边 + 图标冗余，正好接上落地建议 4 |
| B | 新增第五色给达标 | 违背「单一强调色 + 语义克制」，不推荐 |
| C | 维持千问原案，绿色兼任达标 | 与硬约束 2 冲突，需回到需求侧明确改约束；不建议 |

**本文所有样式稿默认按方案 A 出图**，并在图例里标注「待确认」。

## 4. vivo S7 手机端样式规格（Compact / 360dp）

| 项 | 规格 |
|---|---|
| 基准与安全区 | 360dp；**顶部避让刘海 + 状态栏**（≥24dp + notch safe area），底部避让手势导航条（≥16dp）；内容左右边距 **16dp** |
| 导航 | 底部 4 Tab（千问定稿），图标 + 文字，选中态墨蓝 + 琥珀下划线；Tab 高 56–64dp；**不放侧栏** |
| 栏数 | 严格单栏；卡片圆角 16dp、按钮/输入 12dp，间距 8/12/16/24 on 4dp 网格 |
| 触控 | 所有可点区域 **≥48×48dp**；一键跳转外部 App 的按钮 ≥56dp 高（路上单手点） |
| 字号 | 沿用千问 Type Scale（Display 24/700、Title 18/700、Body-Strong 15/600、Caption 13/400），**不放大**；数字/倒计时等宽字形，分钟级刷新不抖动 |
| 动效 | 60Hz + 4000mAh → 不做高频动画、不做秒级刷新；转场 ≤200ms；深色模式用 AMOLED 纯黑底（`#000`）省电，语义色不变（千问落地建议 3） |
| 今日页 | 倒计时主卡（琥珀）置顶 → 今日时间轴（任务/规划/复习同一条线）→ 绿色可学时段叠加；一屏只做「今天几点干什么」 |
| 笔记「双栏对应」 | **compact 下不做真双栏**（360dp 挤）：降级为 **`AI 笔记 / 我的笔迹` 分段切换 + 「笔迹 2」角标跳转**，点角标拉出该 `anchorId` 下的笔迹；两端仍分开存 |
| 全局日历 | 由「今日」下钻进入，月/周视图单栏，任务·规划·校历三层用**形状 + 文字图例**区分，不只靠颜色 |
| 复习闭环 | 20/30 分钟碎片场景的主内容：复述 → AI 纠正 → 练手题，对话流全屏，输入区固定底部 |
| A 通道 | **手机不支持可靠分屏 → 自动降级为「一键跳转 Notein + 自动回位」**，顶部留一条「返回学习会话」常驻提示条 |
| 桌面 Widget | **2×2 / 4×1 小尺寸**（用户要「小一点」）；只显示最近一个任务 + 倒计时 + 一键打开；22dp 圆角跟随系统；**墨蓝实底**（与 App 内暖白底不同，为的是从桌面壁纸里跳出来）；**分钟级刷新**；点组件 → 今日，点任务 → 跳转外部 App；另提供「考前速览态」切换 |
| 教学区域 | 「提醒方式 = 无」时段**不响不亮屏**（AMOLED 亮屏也耗电）；屏幕态速查卡仅在校外/进考场前可用 |
| 打印 | 手机端只做「导出 PDF / 口袋卡」交给外部打印，不做 A4 预览 |

## 5. 联想拯救者 Y900 Pad 端样式规格（Expanded / 横屏宽屏）

| 项 | 规格 |
|---|---|
| 基准 | 横屏有效宽约 1536–1920dp；`smallestWidth ≥ 1024dp`；**按窗口宽度动态判定，不写死**；左右安全边距 24dp，上下 16dp |
| 导航 | **取消底部 4 Tab**，改左侧常驻 `NavigationRail`（96dp；可展开为 240dp 带文字）；4 个目的地仍是今日/规划/笔记/我的；大屏底部 Tab 手指行程太远 |
| 栏数 | **双栏 list-detail 起步**：左列固定 **320–360dp**（时间轴 / 规划列表 / 日历 / 笔记目录），右列弹性（详情 / 会话 / 笔记正文）；≥1200dp 有效宽可上三栏（Rail + 列表 + 详情） |
| 内容最大宽度 | 正文栏 **≤ 720dp** 并居中留白，避免宽屏长行降低可读性；宽出来的空间给并列栏与笔记，不拉伸文字 |
| 字号 | **与手机完全一致**（千问 Type Scale），不因屏大而等比放大——信息克制；大屏增加的是**并列信息量与留白**，不是字号 |
| 触控 / 笔 | 指尖目标 ≥48dp；手写区另按笔尖精度给 **≥8dp 笔迹命中容差 + 防误触（palm rejection）**；144Hz 用于压感笔迹平滑（perfect-freehand）；**压感级数以实机为准，无 pressure 时退化为匀速笔迹** |
| 会话学习引擎 | **pad 最大价值**：左栏视频/题目（16:9 区），右栏内置笔记区（D 通道）常驻，可显隐且隐藏时不占位；阶段进度条横置顶部 |
| 笔记双栏对应 | 千问的「双栏对应」在 **expanded 才真正落地**：左 AI 笔记（结构化文本块），右我的手写（SVG 笔迹），`anchorId` 角标双向跳转；不合订 |
| 费曼复述 | 左对话流（限宽 640dp），右侧常驻 AI 笔记 / 考前速查卡 + 练手题，避免来回切页 |
| 新建规划 | 左表单（目标/75%/15 天/startMode/提前量），右**日历选绿色时段**并实时显示「按容量匹配环节」；手机端的一屏塞不下，这里一屏搞定 |
| 全局日历 | 双栏：左月/周视图，右当日时段池 + 三层叠加图例 + 四来源标记（课程表/模板/自定义/校历活动）；绿色色块只表示「可学习时段」 |
| 薄弱点 / 速查卡 | 左列表 + 右卡片预览；提供**屏幕态 ↔ 打印态切换**与 **A4 / 口袋卡打印预览页**；黑白输出靠描边 + 图标 + 文字冗余编码，不靠颜色 |
| 专注模式 | 599g 桌面支架场景：会话页可全屏隐藏 Rail，只留「退出专注」；不做秒级动画 |
| Widget | Pad 桌面可用 **4×2 较大尺寸**，仍只显示最近一个任务 + 倒计时（信息克制不因屏大放宽）；可常驻「考前速览态」 |
| 打印 | Pad 直接预览并导出黑白 A4 / 口袋卡，供**教学区域用纸质**（禁用电子设备） |

### 5.1 A 通道分屏：三种形态 + 降级（Y900 独占主战场）

| 形态 | 触发 | App 窗口 class | 布局 |
|---|---|---|---|
| **① 系统分屏 50:50 / 60:40** | 检测到多窗口 / Activity Embedding 可用 | **Medium**（宽度骤降） | App 自动切单栏 + NavigationRail；左 App（视频/题目/AI 笔记），右 Notein 手写；顶部「返回学习会话」 |
| **② 自由窗口 / 悬浮窗** | 系统支持自由窗口 | Medium / Compact | App 收成紧凑单栏，Notein 悬浮；笔迹归档仍走 C 通道 PDF 桥接 |
| **③ 一键跳转 + 自动回位** | 分屏不可用或用户关闭 | 全屏 Expanded | 与手机同构；A 通道只登记「外部引用 + 快照」 |
| **④ App 内 D 通道（不依赖系统）** | 用户选择内置笔记区 | 全屏 Expanded | 双栏：左内容、右自研笔迹区，数据 100% 归本地库 |

> **能力探测顺序**：④（内置，永远可用）→ ① → ② → ③。C 通道（PDF 桥接归档）在所有形态下都可补齐「笔迹能带走」这一缺口。原始笔迹写在 Notein 里入不了我们库，只有归档回来的那份可被处理。

## 6. 八个原型：两端布局对照

| 千问原型 | vivo S7（Compact） | Y900（Expanded） |
|---|---|---|

| ② 今日视图 | 单栏：倒计时主卡 → 时间轴 → 绿色时段 | 双栏：左时间轴列表，右「下一任务」主卡 + 日历摘要常驻 |

| ④ 会话学习引擎 | 纵向 5 阶段，视频在上、笔记折叠在下（可显隐） | **左视频/题目 + 右内置笔记区**并列，阶段条横置 |
| ⑤ 费曼复述 / 复习闭环 | 全屏对话流 + 底部输入 | 左对话流（限宽）+ 右 AI 笔记 / 速查卡 / 练手题 |
| ⑥ 笔记双栏对应 | **降级为分段切换 + 角标跳转**（不硬塞双栏） | **真双栏**：AI 笔记 ‖ 我的手写，`anchorId` 双向跳 |
| ⑦ 薄弱点 / 考前速查卡 | 列表 → 点开单条；导出 PDF 交外部打印 | 左列表 + 右卡片；屏幕/打印切换 + **A4 打印预览** |
| ⑧ 我的 / L0 开关 | 分组单栏列表，逐项开关 | 左分组导航 + 右开关面板，一屏看全；数据迁移入口同页 |

## 7. 两端分工矩阵（编码时的判断依据）

| 维度 | vivo S7 | 联想拯救者 Y900 |
|---|---|---|

## 9. 编码落地清单（Flutter）

| 层 | 落地 |
|---|---|
| 断点 | `LayoutBuilder` + `MediaQuery.sizeOf(context).width`；`<600 / 600–840 / ≥840` 三档，**以窗口宽度为准**；分屏导致宽度变化时自动重组，不缓存设备型号 |
| 导航 | Compact → `NavigationBar`（4 Tab）；Medium/Expanded → `NavigationRail` / `NavigationDrawer`；同一份目的地枚举 |
| 规范布局 | 复用 Material 3 canonical layout：List-Detail（双栏）、Supporting Pane（三栏）；`NavigationRail` 96dp / 展开 240dp；左列 320–360dp |
| 主题 | `ThemeData` + `ColorScheme` 扩展槽位映射千问 4 色；**方案 A 下松绿只绑定 `slotAvailable`，达标绑 `primary` + 形状**；深色模式仅反背景层级 |
| 字体系列 | Noto Serif SC（Display/Title）、Sans（Body/Caption）、数字等宽 `fontFeatures: tabularFigures` |
| Widget | `RemoteViews` / `Glance` 尺寸档 2×2、4×1、4×2；分钟级刷新；点击路由区分「组件→今日」「任务→外部 App」 |
| 提醒 | Android 10 + Funtouch 需精确闹钟 + 后台/自启动白名单引导；提前 2/5/自定义；设备禁用时段静默 |
| 笔迹 | `perfect-freehand` 风格压感平滑；pressure 缺省退化；SVG 笔迹随 `.studypack` 导出；防误触 |
| 分屏 | 探测多窗口 / Activity Embedding；三形态 + 降级；宽度回落 Medium 时重组布局；C 通道 PDF 归档 |
| 打印 | 独立黑白打印样式表（描边 + 图标 + 文字冗余），A4 / 口袋卡两种版式，屏幕态与打印态**同源内容** |
| 数据 | 两端共用同一 `.studypack`；`manifest.json` 记录导出设备，跨端导入不做设备假设 |
